# ЛР1 - заготовки промптов для Алисы AI

Выбранный вариант из PDF: **(Ф) «Получить коммерческое предложение»**. Промпты ниже подготовлены для проектирования B2B-формы «Модуль». Они являются заготовками: **в Алису AI не отправлялись**, результат генерации не выдаётся за фактический.

## 1. Аудитория и задача

```text
Ты продуктовый аналитик. Для учебного B2B-лендинга «Модуль» опиши 3 сегмента аудитории, которые могут запросить коммерческое предложение на модульные наборы конструкторов: образовательные организации, корпоративные заказчики и розничные партнеры. Для каждого сегмента укажи задачу, сомнение перед заявкой, обязательные поля формы и один проверяемый сигнал интереса. Не придумывай реальные компании, контакты или статистику. Ответ дай таблицей.
```

**Ожидаемый локальный результат:** таблица аудитории для проверки полей формы.

## 2. Структура одностраничного приложения

```text
Ты UX-архитектор. Составь структуру статического B2B-лендинга «Модуль» для сценария «получить коммерческое предложение». Нужны якорные разделы: hero, о продукте, каталог, о компании, FAQ, контакты и форма заявки. Для каждого раздела укажи цель, один главный призыв к действию и связь со следующим шагом. Не добавляй оплату, доставку, личный кабинет или реальные интеграции.
```

**Ожидаемый локальный результат:** список блоков и переходов для wireframes.

## 3. Тексты и тональность

```text
Ты редактор B2B-лендинга. Напиши черновики на русском языке для «Модуль»: заголовок hero, подзаголовок, три преимущества, короткий текст о компании, три FAQ и текст кнопки формы «Получить коммерческое предложение». Тон спокойный и конкретный, без неподтвержденных цифр, обещаний поставки и упоминания официальной связи с LEGO. В каждом тексте помечай демонстрационные характеристики как учебные.
```

**Ожидаемый локальный результат:** тексты, которые можно проверить вручную перед добавлением в HTML.

## 4. Поля формы

```text
Ты специалист по UX-формам. Спроектируй форму «Получить коммерческое предложение» для B2B-каталога модульных конструкторов. Предложи обязательность и понятную подпись для полей: имя, компания, рабочий email, телефон (необязательно), направление, интересующий набор, количество, комментарий и согласие на сохранение учебной заявки. Добавь сообщения ошибок и правило: реальные персональные данные в учебной версии не вводятся.
```

**Ожидаемый локальный результат:** черновик схемы полей, совпадающий с `form-spec.json`.

## 5. Проверка готового сценария

```text
Ты QA-редактор. Проверь описание учебной формы «Получить коммерческое предложение» и список критериев приемки. Составь позитивные, граничные и ошибочные сценарии: пустые обязательные поля, неверный email, количество меньше минимальной партии, допустимая партия, повторное открытие страницы, экспорт и очистка localStorage. Для каждого сценария укажи Дано, Когда, Тогда. Не утверждай, что тесты реально выполнены.
```

**Ожидаемый локальный результат:** чек-лист для ручной проверки, а не отчет о фактическом запуске.
