# ЛР4 - Kanban и план учебной работы

## Методологии

**Scrum** работает итерациями фиксированной длины. У спринта есть цель, выбранный набор задач и даты начала/окончания; обычно команда планирует спринт, проводит ежедневные встречи, review и retrospective.

**Kanban** организует непрерывный поток задач по колонкам. Работа не обязана ждать границ спринта, но ограничивается WIP: новую задачу не начинают, пока активная работа не завершена или не передана на проверку.

## Выбор

Для локального MVP выбран **Kanban**: объем невелик, фактический состав команды не задан, а документы и демонстрационную витрину удобно завершать последовательно. В учебном комплекте существует плановый период, но он не называется фактически проведенным Scrum-спринтом.

## Колонки

Бэклог -> К выполнению -> В работе -> На проверке -> Готово.

- общий WIP для «В работе»: **2**;
- если работает один известный исполнитель: **личный WIP 1**;
- перед взятием следующей задачи текущая должна перейти на проверку или в готово;
- вернуть задачу из Review в In Progress можно с описанием проблемы и ожидаемого исправления.
