# Выбор вариантов и исходные требования

## ЛР1 - выбранный вариант

Точная формулировка из файла `лр1/Задания для 3ВТба.pdf`:

> **(Ф) «Получить коммерческое предложение».**

В локальном комплекте вариант реализован как спецификация формы для B2B-запроса по каталогам «Модуль». Реальная публикация в Яндекс Формах не выполнялась; подготовлены промпты, схема полей и инструкция.

## ЛР2 - выбранный вариант 4

Точная формулировка из `лр2/569b2571c9daeea0e9ff85edb4b3f71a.docx`:

> разработать одностраничный лендинг для B2B-продаж конструкторов в стиле LEGO. Включает дизайн с нуля, якорное меню, блоки (о продукте, пакеты услуг, о компании, FAQ, контакты), каталог товаров с фильтрами и админкой для редактирования, встраивание видео, форму заявки с интеграцией в CRM/почту, адаптивную верстку, базовое SEO и аналитику

В учебном MVP внешняя CRM/почта заменены на локальное сохранение заявок в `localStorage`. Реальные продажи, оплата, доставка и интеграция с LEGO отсутствуют.

## Обязательные поля задачи по методичке ЛР2

Источник: `лр2/8a327fc4b2aeb86014e97577f69d0dac.docx`.

1. **Детали задачи:** тип, приоритет, метки, окружение, версия исправления.
2. **Блокер/дефект:** описание, предусловия, что случилось, шаги воспроизведения, фактический результат, ожидаемый результат, примечания.
3. **Доработка:** описание, User Story по форме «Как [роль], я хочу [действие], чтобы [ценность]».
4. **Критерии приемки:** проверяемые условия в формате «Дано + Когда + Тогда».
5. **Дополнительные материалы:** макеты/дизайн, API, аналоги, документация.
6. **Нефункциональные требования:** устройства (десктоп/мобильные/все) и изменения бэкенда/API.
7. **Связи и подзадачи:** связи с задачами; подзадачи для аналитики, бэкенда, фронтенда, тестирования, UX/UI, документации и DevOps с назначением исполнителя.

Файл `lab2/backlog.csv` повторяет эти поля для каждой записи. Для учебной локальной работы исполнителем указан только известный участник: А.А. Первых; остальные участники и контакты не заданы.
